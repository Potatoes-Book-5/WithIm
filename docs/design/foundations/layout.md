# Display Layout

> 확인일: 2026-11-13 · 상태: 초안. 공식 [Display Layout](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout) 페이지의 일러스트 SVG에서 도형 좌표를 측정한 값입니다. 페이지 본문에는 수치가 없으므로 공식 `.fig`로 확인해야 합니다(T-002).

## 기준 디스플레이

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | Connect-L 12.9인치, 16:9 | 공식 페이지의 디스플레이 목록 |
| Figma 프레임 | 2560×1440 px | 팀 결정. 요청한 12.8인치에 가장 가까운 공식 기준이 12.9인치 |
| 픽셀 밀도 | 약 228 ppi, 1px ≈ 0.111mm | 2560×1440, 12.9인치로 계산 |
| 운전석 | 왼쪽(좌핸들) | 공식 일러스트 기준 |

## 영역 (2560×1440 기준)

공식 일러스트는 1920×1080 기준으로 그려져 있어 4/3배로 환산했습니다.

| 영역 | x | y | 너비 | 높이 |
|---|---|---|---|---|
| 상태바 | 0 | 0 | 2560 | 112 |
| Driving View | 0 | 112 | 837 | 1140 |
| 앱 영역 Landscape | 837 | 112 | 1699 | 1140 |
| 앱 영역 Portrait A | 837 | 112 | 837 | 1140 |
| 앱 영역 Portrait B | 1698 | 112 | 838 | 1140 |
| 하단 독 | 0 | 1252 | 2560 | 188 |

- 앱 영역 오른쪽 여백은 24px, Portrait 창 사이 간격은 24px입니다.
- 앱은 Driving View를 가릴 수 없습니다(SM-001).
- `screenOrientation`을 지정하지 않으면 Portrait 창 1개로 실행됩니다.

## 에뮬레이터 실측 (2026-11-14)

Pleos Connect Emulator v2.1.0에서 직접 확인한 값입니다. 공식 일러스트와 다릅니다.

| 항목 | 값 | 확인 방법 |
|---|---|---|
| 화면 | 2560×1440 | `adb shell wm size` |
| AVD 설정 밀도 | 160dpi | `hw.lcd.density`, `wm density` |
| 앱 창 실제 밀도 | **229dpi** (1dp ≈ 1.43px) | `dumpsys activity`의 앱 설정 |
| Driving View | 없음. 앱이 가로 전체를 사용 | 스크린샷 |
| 앱 창 | 2560×1268 (상태바 76px, 하단 독 96px) | 스크린샷 |

- 코드에서는 와이어프레임 px 값을 `wpx`·`wsp` 단위로 적어 229dpi 기준으로 환산합니다(`ui/theme/Dimens.kt`).
- 실차에서 Driving View와 창 분할이 일러스트대로 나오는지는 확인이 필요합니다.

## 크기 기준

공식 수치를 px로 환산한 값과 팀 제안값입니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 중요 정보 글자 높이 5mm | 약 45px 이상 | DG-008 환산. 와이어프레임은 64px 이상 사용 |
| 보조 정보 글자 높이 3mm | 약 27px 이상 | DG-008 환산. 와이어프레임은 32px 이상 사용 |
| 최소 글자 높이 | 18px | TYP-002 |
| 터치 영역 최소 높이 | 120px(약 13mm) | 팀 제안값. 공식 수치 없음 |
| 화면 가장자리 여백 | 48px | 팀 제안값 |

글자 높이를 대문자 높이와 글꼴 크기 중 무엇으로 재는지는 원문에 없습니다. 실제 기기에서 확인이 필요합니다.
