# T-045 명세 발화별 내부 실행 경로

## 목표
S-012/F-010의 발화를 정규화한 intent에 대해 실제 UseCase/저장소/읽기 모델을 연결한다. 발화→의도 해석(Gleo) 검증과 정규화 intent→문맥/실제 데이터 처리의 단위 검증을 분리한다. 관심 지역·진입·추천·분석·내비·브리핑을 포함한 명시적 발화 추적표를 만든다.

## 범위와 결정
- 관심 지역/브리핑/진입 기록은 Room v5에 저장하고 기존 v1~4 데이터를 보존한다(ADR-012).
- 내부 App API는 저장·영역 확인·추천·분석·브리핑/읽음·내비 요청을 구현한다. 공개 debug receiver는 위치/개인 저장소/탐색 이력을 노출하지 않는 정책을 유지한다. Gleo 세 함수 제한과 공개 승인 문제를 단위 테스트로 대체하지 않는다.
- 주행 데이터는 기존 실제 MOLIT/Vworld 경로를 사용한다. 추가 원천을 가장하지 않는다. 공식 RSS 뉴스와 청약홈 클라이언트를 분리하고 별도 청약 키 미구성은 UNCONFIGURED로 반환한다. 실제 가격 집계 갱신 브리핑을 제공한다.
- 역세권은 공식 장소 좌표가 준비된 500m 원, 시군구는 실제 코드로 식별하되 경계 기하가 없으면 내부/진입을 추정하지 않는다. 법정동을 원으로 가장하지 않는다.
- 준비된 시장/상세 데이터를 읽고, 무거운 수집은 백그라운드다. 실제 provider HTTP를 매 단위 테스트마다 호출하지 않는다. 단위 테스트는 실제 구현+제어된 원천/시계/포트 fixture이며 실공급자 probe는 별도다.
- 내비는 공식 NaviHelper를 지원/권한 확인 후 vehicle 경계에서만 호출한다. 기존 SDK/JDK/AGP 버전은 유지한다. 출입구 좌표 미제공은 확인 요청이다. 요청 접수와 안내 시작을 구분한다.
- 카메라/자동 발화/시동 자동형은 실제 지원 Gate 확인 전 실행하지 않는다. 미지원/주행 차단 분기를 검증하며 정상 기능 완료로 세지 않는다.

## 검증
173개 기존 JVM 회귀를 유지하고 발화 단위 정상/모호/빈/오류/프로필·동의/만료 테스트를 추가한다. DB 재열기와 v4→5는 Pleos 계측으로 검증한다. 실제 HTTP가 거부되면 실패를 숨기지 않는다. 원문 발화의 이해 정확성·STT·실차 SDK 지원은 별도 Gate로 남긴다.
