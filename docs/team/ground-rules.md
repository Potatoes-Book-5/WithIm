# 그라운드 룰

수치는 제안값이며 팀 합의 후 확정합니다.

## 작업 방식

1. 모든 작업은 [tracking/tasks.md](../tracking/tasks.md)에 T-ID를 등록한 뒤 시작합니다.
2. 한 작업의 담당자는 한 명입니다. 공동 작업이면 작업을 나눕니다.
3. 착수할 때 상태를 `doing`으로 바꾸고, 막히면 즉시 `blocked`로 바꿉니다.
4. 같은 파일을 동시에 크게 수정할 때는 먼저 담당자끼리 조율합니다.

## 문서

1. 같은 사실은 한 곳에만 쓰고 나머지는 링크합니다.
2. 규칙 우선순위는 Pleos 공식 가이드 → `principles/`·`platform/` → 기능 문서 순입니다.
3. 중요한 결정은 구두 합의로 끝내지 않고 `decisions/`에 기록합니다.
4. 코드 동작이 바뀌면 관련 문서를 같은 PR에서 수정합니다.

## 리뷰

1. PR은 한 가지 목적만 담고 작게 유지합니다.
2. 리뷰 요청 후 1영업일 안에 응답합니다(제안값).
3. 리뷰는 코드와 결과에 대해 말하고, 지적에는 이유나 대안을 함께 적습니다.

## 안전과 보안

1. 키와 `local.properties`를 커밋하거나 메시지로 공유하지 않습니다.
2. 실제 위치 데이터와 개인정보를 테스트 자료, 로그, 스크린샷에 넣지 않습니다.
3. 주행 안전 규칙(`DD`, `DR`)은 일정보다 우선합니다.

## 개선

같은 문제가 두 번 생기면 [learnings](../learnings/README.md)에 기록하고 규칙이나 검사로 승격합니다.
