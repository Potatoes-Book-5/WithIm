# 국토부 아파트 매매 실거래가 조회

T-020, [ADR-006](../decisions/ADR-006-molit-retrofit.md)의 구현 사용법이다. 국토교통부의 [아파트 매매 실거래가 상세 자료](https://www.data.go.kr/data/15126468/openapi.do)를 `Retrofit`으로 조회한다.

## 설정

발급받은 서비스 키를 git 제외 파일 `local.properties`의 `MOLIT_API_KEY`에 넣는다. 없으면 사용자 Gradle 속성, 그다음 빌드 환경 변수 `MOLIT_API_KEY`(CI)에서 찾는다. 코드, 문서, 저장소 설정 파일에 키를 쓰지 않는다. 키가 없으면 조회 결과는 `DomainError.MissingApiKey`다. 앱의 `BuildConfig`에 들어간 키는 APK에서 추출될 수 있으므로 배포용 키 관리 방식은 별도로 결정해야 한다.

## 호출

`RealEstateApplication.container.getApartmentTrades`가 `GetApartmentTradesUseCase`다. 예를 들어 2026년 9월의 강남구 거래 첫 페이지는 `getApartmentTrades("11680", YearMonth.of(2026, 9), pageNumber = 1, pageSize = 100)`으로 요청한다. 결과는 `Outcome<TradePage>`이며 다음 페이지 존재 여부는 `TradePage.nextPage`로 확인한다. 지역 코드 5자리와 계약 연월 6자리 기준의 조회이므로 도로명 주소를 직접 검색하는 API는 아니다.

가격 단위는 **만원**, 면적 단위는 **제곱미터**다. 공식 응답에 없는 선택 정보는 `null`로 둔다. 취소 관련 필드의 제공값은 원문으로 보존하며, 의미가 확인되지 않은 상태값을 임의로 해석하지 않는다. HTTP 상태, 제공기관 오류, 응답 형식 오류, 네트워크 단절과 시간 초과는 `DomainError`로 구분한다.

## 검증과 현재 범위

기존 개발 브랜치에서 에뮬레이터 앱을 실행해 국토부 API를 직접 호출했고, 2026년 9월 영통구의 실제 거래 응답 3건이 앱에 표시되는 것을 확인했다. 이 PR에는 조회 계층과 앱 컨테이너 연결만 포함한다. 빌드 및 문서 검사를 통과했으며 별도의 테스트 코드는 추가하지 않았다.

위 검증은 T-020 당시의 기록이다. 현재 순위·상세는 실거래 응답을 사용하고, [Vworld](vworld-api.md)로 주소와 지역을 확인한다. 상세 세대수는 [K-APT](kapt-api.md)로 보충한다. 현재 조회 범위와 가격 기준은 [F-002](../product/features/F-002-nearby-price-lookup.md)를 따른다.

## 이동 중 메모리 캐시 (T-036)

실거래 응답은 `(시군구 코드, 계약 연월)`별로 실제 수신 완료 시각부터 5분 재사용한다. 오류 응답을 거래 없음으로 저장하지 않는다. 조회 기간이 바뀌거나 해당 키가 없거나 만료되면 필요한 월만 다시 요청한다. 순위의 기준 시각은 사용한 월별 응답 중 가장 오래된 수신 시각이며, 캐시로 재계산했다고 새 조회 시각으로 갱신하지 않는다.

이동 요청은 하나의 스캔이 처리하는 동안 최신 한 개만 대기시킨다. A 처리 중 B·C·D가 오면 A의 응답·오류·타임아웃을 처리한 뒤 D만 시작한다. 지역·출처가 바뀌어도 진행 중인 네트워크 작업을 취소하지 않으며 세대·라운드·위치 검증으로 이전 결과의 화면 반영을 차단한다. 앱 실행 스코프 종료・위치 동의 철회・권한 상실 시 취소는 유지한다. 영구 거래 캐시나 좌표 DB는 추가하지 않는다. 1위 변경 알림의 같은 지역 5분 제한과 10초 표시는 변경하지 않는다.
