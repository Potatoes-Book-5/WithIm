# 하드웨어 접근 정책

> 확인일: 2026-11-08 · 상태: 초안. 페이지 요약을 바탕으로 작성했으며 T-006에서 원문과 대조합니다.
> 공식 문서를 복제하지 않고 요약합니다. 판단이 필요하면 원문을 우선합니다.

## 원문

- [하드웨어 접근 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/platform-api-architecture)

## 요약

차량 기능은 표준 플랫폼 API로만 접근합니다. 주행 중 네트워크 단절에 대비해야 합니다.

## 규칙

강도(MUST/SHOULD)는 원문 표현을 바탕으로 팀이 해석한 값입니다.

| ID | 강도 | 규칙 |
|---|---|---|
| HW-001 | MUST | 하드웨어 기능은 SDK 등 표준 플랫폼 API로만 사용한다. |
| HW-002 | MUST | 차량의 물리적 제어 장치와 센서에 직접 접근하지 않는다. |
| HW-003 | MUST | 모바일 API를 쓸 때는 차량 환경 지원 여부를 먼저 확인한다. |
| HW-004 | SHOULD | 차량에서 불필요한 기능은 제거하거나 선택적 구조로 설계한다. |
| HW-005 | SHOULD | 최근 사용한 콘텐츠를 로컬에 캐시해 오프라인에서도 표시한다. |
| HW-006 | SHOULD | 요청에 재시도 로직과 적절한 타임아웃을 적용한다. |
| HW-007 | SHOULD | 네트워크가 끊기면 오프라인 안내 UI로 알린다. |

## 이 앱에 적용

- SDK 호출은 `vehicle/` 패키지에 격리합니다(ADR-002).
- 시세 응답 캐시는 F-002에서 정의합니다.

## 원문에 없는 항목

- 재시도 횟수와 타임아웃 수치
