# F-010 Gleo 대화형 앱 제어

## 목적

Gleo 음성 요청을 지역 가격 조회·관심 지역 저장·관심 지역 브리핑에 연결한다. 상태는 초안이며 실제 Gleo 등록·권한·주행 허용이 전제다.

## 사용자 가치

- 운전 중 화면을 찾지 않고 질문하고 지역을 기억한다.
- 음성 해석과 실제 데이터 처리를 구분하여 결과에 근거를 제공한다.

## 비즈니스 규칙

### R-GLEO — 함수 계약

최대 3개 제한에 맞춰 다음 구성을 제안한다. 실제 앱 마켓 심사/스키마 승인 전의 예시이며 자동 발화나 시동 이벤트 API를 포함하지 않는다.

| 함수 | 선택 입력 | 처리 | 기본 component |
|---|---|---|---|
| GET_AREA_PRICE_SUMMARY | target: enum, areaQuery: string | 현재 또는 지정 지역의 가격 요약 | service |
| SCRAP_APARTMENT | 없음 | 현재 상세 또는 보이는 관심 매물 Nudge의 단지를 멱등 스크랩 | service |
| GET_REAL_ESTATE_BRIEFING | 없음 | 활성 프로필 관심 지역 변동 요약 | service |

- MVP의 음성 입력은 지역 지정으로 제한한다. 면적·기간은 F-002의 저장 조건/기본값을 사용하며, 발화만으로 면적 필터를 바꾸는 기능은 지원 범위가 아니다. 원래 발화가 앱에 전달된다고 가정하지 않는다.
- 각 함수는 앱에서 권한·상태·입력을 확인한다. 알 수 없는 action이나 파라미터 타입 오류는 실행하지 않는다.
- 설명은 영어로 작성하고 구체 발화 예시는 schema description에 넣지 않는다. 스키마 예시는 별도 JSON 파일에 있다.
- 앱의 기본 응답 기한은 Action 수신 후 5초, 원문에는 Gleo 7초 timeout이 명시되어 있다. 마감 이후 응답/재생을 추가로 시작하지 않는다. 저장의 결과가 불명확하면 재조회하여 중복 없는 결과로 복구한다.
- 앱은 필요한 근거를 Callback data의 JSON 배열 문자열로 반환한다. Gleo 최종 문구는 고정 문자열 일치가 아닌 사실·숫자·대상 지역의 정확성으로 검증한다.
- Gleo가 답변하는 요청은 앱 TTS가 중복 재생하지 않는다. 앱 TTS를 쓰는 승인된 경로에서는 Callback의 silent 설정을 검증한다.
- Gleo가 실제 사용자에게 말할 때 원천 기준일/면적 조건을 누락하거나 숫자를 바꾸지 않는지 별도의 E2E 검증이 필요하다.

### R-CONTEXT — 지역과 요청 문맥

‘이 동네’ 해석 순서는 명시한 지역 → 같은 프로필·세션의 직전 지역 조회 결과(60초 이내) → Action 수신 시점의 유효한 현재 위치이다. 동명이거나 경계가 불명확하면 asking으로 확인한다. 60초는 제안값이다.

Gleo가 실제 발화 시작 시각이나 차량 좌표를 제공한다고 가정하지 않는다. 앱이 Action을 수신할 때 위치·시각을 스냅샷으로 저장한다. ‘지금 현재 위치’라고 명시한 경우에는 직전 대화 문맥보다 새 위치를 우선한다. 명시 의도 분류의 정확성은 실제 Gleo E2E 테스트로 검증한다.

위치 스냅샷은 제안 기준으로 10초 이내이며 보고된 오차 반경이 50m 이내일 때 사용한다. 경계와 오차 범위가 겹치면 특정 동으로 단정하지 않는다. SDK에서 제공하는 정확도/신뢰도 필드의 단위는 레퍼런스 검증 후 매핑한다. 50m는 SDK 필드 값을 추측한 것이 아닌 제품의 정규화된 오차 기준이다.

문맥 모델은 AreaContext(프로필·세션·안정적 지역 ID·공간 범위·위치 스냅샷 시각·생성/만료 시각), RequestContext(내부 요청 ID·프로필/세션·요청 세대·Action·지역·시작/마감 시각)를 갖는다. 가격·관심 지역·브리핑 모델은 각 기능 문서를 따른다.

Gleo가 요청 ID를 전달한다는 보장은 없다. 앱 내부 요청 ID와 Gleo 응답 상관관계 지원 여부는 구분한다. 관심 지역의 저장 무결성은 [F-011](F-011-interest-area-booking.md)을 따른다.

### R-01 — 가격 질의 흐름

- 트리거: 사용자가 Gleo에 현재/지정 지역 가격을 묻는다.
- 선행 조건: 허용된 실행 상태, 활성 프로필, 위치 동의(현재 위치 요청일 때), 사용 가능한 지역/가격 자료.
- 흐름: 문맥 확정 → 같은 필터의 평균·최고 거래 조회 → 출처/기준일 포함 Callback → Gleo 응답.
- 입력이 불명확하면 asking, 위치/데이터 사용 불가 또는 내부 5초 기한 초과면 fail. 조회 성공이나 거래 0건은 success와 명시적인 빈 결과로 표현할 수 있다.
- 오프라인은 유효 캐시일 때만 과거 수집 시각을 밝혀 답한다. 캐시 없음/만료는 최신 가격을 추정하지 않는다.
- 백그라운드 Action은 허용된 경로에서만 처리하며 임의로 상세 Activity를 띄우지 않는다. 위치 SDK 미지원 시 현재 위치 조회를 중단하고 주차 후 명시 지역 선택 경로를 제공한다.
- 인수 조건: 답변에는 지역·평균과 최고 거래의 의미가 맞고, 표본/시점이 Callback data에 포함된다. 원천에 없는 가격·단지를 생성하지 않는다.
- 합성 답변 예: ‘가상마을 A의 최근 90일 전용 80~90㎡ 매매 5건 평균은 12억 원입니다. 같은 조건 최고 거래는 가상 푸른아파트 15억 5천만 원입니다.’

### R-AREA-CHECK — 요청형 관심 지역 확인과 추천

사용자가 “Gleo, 여기가 광교중앙역 인근인 건가?”라고 묻는 STEP 3 확장이다. 자동 진입 알림과 별도로 요청에 응답한다. 대표 발화는 “지금 내가 저장해 둔 관심 지역에 들어온 거야?”, “여기서 우리 조건에 맞는 아파트는 어디야?”다. 이는 제품 요구사항이며 현재 dummy action의 지원 완료를 뜻하지 않는다.

1. 자연어와 해석 문맥으로 확인 대상 지역을 식별한다. 명시한 지역은 비교 대상이며, 차량이 해당 지역 안에 있다는 증거로 쓰지 않는다. 동명이거나 후보가 여럿이면 asking으로 확인한다. 앱 context를 Gleo의 해석 단계에 전달하는 공식 경로는 미결이다.
2. 앱이 Action 수신 시점의 차량 위치·정확도·관측 시각, 활성 프로필·동의·UX 상태, 대상의 안정적 지역 ID·영역 정의, 선호 조건을 확보한다. “여기”의 기준 위치는 현재 위치로 고정하며 직전 조회 지역으로 대체하지 않는다. F-010 R-CONTEXT의 위치 유효성 기준을 적용하고 지도용 임시 기준 좌표는 사용하지 않는다.
3. 위치 오차와 영역 경계로 INSIDE / OUTSIDE / UNCERTAIN을 판정한다. 위치 자체가 없거나 만료·미지원이면 fail로 확인 불가를 안내한다. 대상은 확정됐지만 경계/정확도로 내부 여부를 단정할 수 없으면 UNCERTAIN을 반환한다. 이름이 불명확한 asking과 구분한다. 영역 기준은 F-011의 저장 경계 또는 확인된 중심·반경이며 '인근'의 범위를 응답 근거에 포함한다.
4. 활성 프로필의 관심 지역 저장 여부를 별도 확인한다. 저장 기록이 없으면 관심 지역으로 설정했다고 말하지 않는다. 저장 여부 확인 실패는 미저장으로 취급하지 않고 UNKNOWN으로 표시한다.
5. 확인된 대상 지역과 위치 스냅샷을 고정해 선호 조건에 맞는 추천 및 F-002/F-003 기준 실거래 순위를 조회한다. 추천은 F-004의 조건과 근거를 사용하며, 현재 구 안 3km 순위 범위·기간과 대상 역세권 영역은 별개로 표시한다. 조회 중 영역/기간을 조용히 확장하거나 다른 지역 자료를 붙이지 않는다.
6. 지역 판정·저장 여부·진입 이력·추천·순위·기준 시각을 구조화한 결과로 반환한다. 화면과 Callback은 동일 요청·지역·조회 세대의 결과를 사용한다. 후속 UI는 같은 도메인 결과를 MVI 상태로 반영하며 adapter가 ViewModel/Reducer를 직접 호출하지 않는다. 이동·프로필 전환 후 무효한 결과는 현재 화면에 적용하지 않는다.

#### 응답 사실성

| 근거 | 허용 응답 예 |
|---|---|
| INSIDE + 저장됨 + 같은 방문의 검증된 진입 이력 | “네, 관심 지역으로 설정하신 광교중앙역 인근에 진입했습니다.” 진입 시각도 결과에 포함 |
| INSIDE + 저장됨 + 진입 이력 없음 | “네, 관심 지역으로 설정하신 광교중앙역 인근입니다.” |
| INSIDE + 저장 안 됨 | “네, 광교중앙역 인근입니다.” 관심 지역 설정을 주장하지 않음 |
| OUTSIDE | “현재는 해당 영역 밖입니다.” 질문의 긍정 답변이나 진입 완료를 만들지 않음 |
| UNCERTAIN 또는 위치 사용 불가 | “현재 위치로는 해당 영역 안인지 확실히 확인하기 어렵습니다.” 불확실성 이유를 구분 |

- “진입했습니다”는 같은 프로필·대상·현재 방문의 유효한 outside→inside 기록으로만 말한다. 내부 첫 기동, 위치 입력 재개, 오래된 이전 방문 기록으로 진입을 만들어내지 않는다. 진입 중복 억제와 기록의 유효성은 F-011을 따른다.
- 추천을 확인한 경우에만 “선호 조건에 맞는 AA 아파트를 추천합니다”를 이어 말한다. 추천 없음·조회 실패를 구분한다. 지역 확인 성공 후 추천 공급자만 실패하면 확인 결과와 추천 확인 불가를 함께 반환한다.
- 가격 왕관은 실거래가 순위 1위, 맞춤 추천은 선호 조건에 따른 별도 결과다. 추천 단지에 가격 1위 왕관을 붙이지 않는다. 지도 밖 1위를 화면 안 가짜 좌표로 옮기지 않는다.
- 이번 발화에 대한 응답은 자동 발화 opt-in으로 취급하지 않고 관심 지역을 새로 저장하지 않는다. 주행·신호 대기 시 기존 허용 Gate를 유지하며 상세 화면을 강제로 열지 않는다. Parking에서는 허용된 요약을 표시하고, 오프라인은 유효 위치·저장 경계·캐시만 사용하며 기준 시각을 밝힌다. 백그라운드는 허용된 요청형 경로만 처리한다.

#### 스키마 확장안과 인수 조건

기존 3개 함수에 네 번째 함수를 단순 추가하지 않는다. 가격 조회 함수를 `GET_AREA_OVERVIEW`로 확장하고 PRICE_SUMMARY / LOCATION_CHECK 목적을 구분하는 안을 제안한다. 저장·브리핑 함수는 별도 유지한다. 이름·파라미터·기존 호출 호환성은 후속 결정 사항이다. 현재 assets/schema.json·기존 실행 API를 이 문서 변경으로 교체하거나 지원 완료로 표시하지 않는다. [외부 계약의 확장안](../../api/gleo-intent-adapter.md), [내부 API 확장 요구](../../api/app-action-api.md)를 함께 따른다.

- [ ] 자연어 대상 지역과 실제 현재 위치를 별도로 확보한 뒤 비교한다.
- [ ] 현재 내부/실제 진입/관심 저장 여부를 독립적인 근거로 검증한다.
- [ ] 추천과 왕관의 단지가 달라도 응답·화면이 각각의 의미를 유지한다.
- [ ] 위치/경계/프로필/캐시/공급자 실패가 긍정 답변이나 허위 추천으로 바뀌지 않는다.
- [ ] Callback과 화면이 같은 대상·조회 기준을 사용하며 이전 세대 결과를 폐기한다.

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | action, areaQuery | 지정 지역 또는 현재/직전 문맥. 누락/타입 검사 |
| 입력 | 활성 프로필·UX·위치 스냅샷 | 앱이 수신 시점에 확보 |
| 출력 | success/asking/fail Callback | 사실 근거와 대상 지역, 실제 실행 결과 |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 요청형 함수 사용, 상세 진입은 상태 매트릭스 적용 |
| Drive / 신호 대기 | 주행 음성/실행 경로 허용 확인 전 비활성 |
| 오프라인 | F-002 유효 캐시 요약, F-011 로컬 저장, F-013 과거 브리핑 |
| API 미지원 | 현재 위치/음성 실행을 가장하지 않고 확인 또는 fail |
| 백그라운드 | 승인된 Action 경로만; 상세 Activity 강제 실행 금지 |

## 예외

- 모호한 지역은 asking. 잘못된 action/타입은 부작용 없이 거부한다.
- 가격이 없거나 일부 조회가 실패하면 근거 없는 값으로 채우지 않는다.
- 프로필/권한/요청 세대가 바뀌면 이전 결과를 노출하지 않는다.

## 인수 조건

- [ ] 함수 선택·입력값·최종 음성 사실성을 Gleo E2E로 확인한다.
- [ ] 지역·숫자·단위·시점이 F-002 결과와 일치한다.
- [ ] 앱 Callback은 제안 마감 내 한 번 처리하며 지연 응답을 발화하지 않는다.
- [ ] Gleo 응답과 앱 TTS가 중복되지 않는다.

## T-040 Nudge 기반 실행 문맥

현재 schema는 가격·단지 스크랩·브리핑 세 함수다. 지역 저장 SAVE_INTEREST_AREA는 debug 호환 호출만 유지하고 schema에서 제외한다. 단지 스크랩과 관심 지역 저장은 다른 명령이다.

SCR-005의 ‘스크랩해 줘’ 제안이 보이는 동안 해당 단지 ID와 배너 key를 문맥에 담는다. 현재 실제 표시 중인 상세가 있으면 그 단지, 그렇지 않으면 보이는 Nudge를 사용한다. 주행 화면 뒤의 상세, P 전환으로 숨겨진 배너, 만료된 배너, 마지막 대장을 추정해 쓰지 않는다. 앱 foreground·온보딩·동의 조건을 확인하고 Action 수신 시 snapshot을 고정한다. 상세 조회 뒤에도 실행 세대가 유효한지 재검증한다.

실제 단지 스크랩은 로컬 저장을 수행하며 음성 재요청과 배너 탭은 동일 ensure-saved 명령을 사용한다. 성공 후 DB 관찰로 배너와 상세의 스크랩 상태를 갱신한다. 이미 저장된 단지는 다시 저장하거나 해제하지 않는다. 가격·지역 저장·브리핑의 dummy 계약은 유지한다. 명시 단지명 검색·‘두 번째’ 같은 순위 지시는 이번 SCRAP_APARTMENT의 지원 범위가 아니며 schema description으로 지원을 가장하지 않는다.

앱 context가 Gleo에 자동 전송된다고 가정하지 않는다. 자연어 해석 및 자체 대화 context는 Gleo, 실행 snapshot·대상 검증·데이터 조회·저장·callback은 앱 책임이다. [실행 계약](../../api/voice-context.md), [E2E](../../testing/gleo-tour/e2e.md).
