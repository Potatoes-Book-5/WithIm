# F-010 Gleo 대화형 앱 제어

## 목적

Gleo 음성 요청을 지역 가격 조회·관심 지역 저장·관심 지역 브리핑에 연결한다. 상태는 초안이며 실제 Gleo 등록·권한·주행 허용이 전제다.

## 사용자 가치

- 운전 중 화면을 찾지 않고 질문하고 지역을 기억한다.
- 음성 해석과 실제 데이터 처리를 구분하여 결과에 근거를 제공한다.

## 비즈니스 규칙

### R-GLEO — 함수 계약

최대 3개 제한에 맞춰 다음 구성을 제안한다. 실제 앱 마켓 심사/스키마 승인 전의 예시이며 자동 발화나 시동 이벤트 API를 포함하지 않는다.

| 함수 | 선택 입력 | 처리 | 기본 component |
|---|---|---|---|
| GET_AREA_PRICE_SUMMARY | areaQuery: string | 현재 또는 지정 지역의 가격 요약 | service |
| SAVE_INTEREST_AREA | areaQuery: string | 문맥/현재/지정 관심 지역 저장 | service |
| GET_REAL_ESTATE_BRIEFING | 없음 | 활성 프로필 관심 지역 변동 요약 | service |

- MVP의 음성 입력은 지역 지정으로 제한한다. 면적·기간은 F-002의 저장 조건/기본값을 사용하며, 발화만으로 면적 필터를 바꾸는 기능은 지원 범위가 아니다. 원래 발화가 앱에 전달된다고 가정하지 않는다.
- 각 함수는 앱에서 권한·상태·입력을 확인한다. 알 수 없는 action이나 파라미터 타입 오류는 실행하지 않는다.
- 설명은 영어로 작성하고 구체 발화 예시는 schema description에 넣지 않는다. 스키마 예시는 별도 JSON 파일에 있다.
- 앱의 기본 응답 기한은 Action 수신 후 5초, 원문에는 Gleo 7초 timeout이 명시되어 있다. 마감 이후 응답/재생을 추가로 시작하지 않는다. 저장의 결과가 불명확하면 재조회하여 중복 없는 결과로 복구한다.
- 앱은 필요한 근거를 Callback data의 JSON 배열 문자열로 반환한다. Gleo 최종 문구는 고정 문자열 일치가 아닌 사실·숫자·대상 지역의 정확성으로 검증한다.
- Gleo가 답변하는 요청은 앱 TTS가 중복 재생하지 않는다. 앱 TTS를 쓰는 승인된 경로에서는 Callback의 silent 설정을 검증한다.
- Gleo가 실제 사용자에게 말할 때 원천 기준일/면적 조건을 누락하거나 숫자를 바꾸지 않는지 별도의 E2E 검증이 필요하다.

### R-CONTEXT — 지역과 요청 문맥

‘이 동네’ 해석 순서는 명시한 지역 → 같은 프로필·세션의 직전 지역 조회 결과(60초 이내) → Action 수신 시점의 유효한 현재 위치이다. 동명이거나 경계가 불명확하면 asking으로 확인한다. 60초는 제안값이다.

Gleo가 실제 발화 시작 시각이나 차량 좌표를 제공한다고 가정하지 않는다. 앱이 Action을 수신할 때 위치·시각을 스냅샷으로 저장한다. ‘지금 현재 위치’라고 명시한 경우에는 직전 대화 문맥보다 새 위치를 우선한다. 명시 의도 분류의 정확성은 실제 Gleo E2E 테스트로 검증한다.

위치 스냅샷은 제안 기준으로 10초 이내이며 보고된 오차 반경이 50m 이내일 때 사용한다. 경계와 오차 범위가 겹치면 특정 동으로 단정하지 않는다. SDK에서 제공하는 정확도/신뢰도 필드의 단위는 레퍼런스 검증 후 매핑한다. 50m는 SDK 필드 값을 추측한 것이 아닌 제품의 정규화된 오차 기준이다.

문맥 모델은 AreaContext(프로필·세션·안정적 지역 ID·공간 범위·위치 스냅샷 시각·생성/만료 시각), RequestContext(내부 요청 ID·프로필/세션·요청 세대·Action·지역·시작/마감 시각)를 갖는다. 가격·관심 지역·브리핑 모델은 각 기능 문서를 따른다.

Gleo가 요청 ID를 전달한다는 보장은 없다. 앱 내부 요청 ID와 Gleo 응답 상관관계 지원 여부는 구분한다. 관심 지역의 저장 무결성은 [F-011](F-011-interest-area-booking.md)을 따른다.

### R-01 — 가격 질의 흐름

- 트리거: 사용자가 Gleo에 현재/지정 지역 가격을 묻는다.
- 선행 조건: 허용된 실행 상태, 활성 프로필, 위치 동의(현재 위치 요청일 때), 사용 가능한 지역/가격 자료.
- 흐름: 문맥 확정 → 같은 필터의 평균·최고 거래 조회 → 출처/기준일 포함 Callback → Gleo 응답.
- 입력이 불명확하면 asking, 위치/데이터 사용 불가 또는 내부 5초 기한 초과면 fail. 조회 성공이나 거래 0건은 success와 명시적인 빈 결과로 표현할 수 있다.
- 오프라인은 유효 캐시일 때만 과거 수집 시각을 밝혀 답한다. 캐시 없음/만료는 최신 가격을 추정하지 않는다.
- 백그라운드 Action은 허용된 경로에서만 처리하며 임의로 상세 Activity를 띄우지 않는다. 위치 SDK 미지원 시 현재 위치 조회를 중단하고 주차 후 명시 지역 선택 경로를 제공한다.
- 인수 조건: 답변에는 지역·평균과 최고 거래의 의미가 맞고, 표본/시점이 Callback data에 포함된다. 원천에 없는 가격·단지를 생성하지 않는다.
- 합성 답변 예: ‘가상마을 A의 최근 90일 전용 80~90㎡ 매매 5건 평균은 12억 원입니다. 같은 조건 최고 거래는 가상 푸른아파트 15억 5천만 원입니다.’

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | action, areaQuery | 지정 지역 또는 현재/직전 문맥. 누락/타입 검사 |
| 입력 | 활성 프로필·UX·위치 스냅샷 | 앱이 수신 시점에 확보 |
| 출력 | success/asking/fail Callback | 사실 근거와 대상 지역, 실제 실행 결과 |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 요청형 함수 사용, 상세 진입은 상태 매트릭스 적용 |
| Drive / 신호 대기 | 주행 음성/실행 경로 허용 확인 전 비활성 |
| 오프라인 | F-002 유효 캐시 요약, F-011 로컬 저장, F-013 과거 브리핑 |
| API 미지원 | 현재 위치/음성 실행을 가장하지 않고 확인 또는 fail |
| 백그라운드 | 승인된 Action 경로만; 상세 Activity 강제 실행 금지 |

## 예외

- 모호한 지역은 asking. 잘못된 action/타입은 부작용 없이 거부한다.
- 가격이 없거나 일부 조회가 실패하면 근거 없는 값으로 채우지 않는다.
- 프로필/권한/요청 세대가 바뀌면 이전 결과를 노출하지 않는다.

## 인수 조건

- [ ] 함수 선택·입력값·최종 음성 사실성을 Gleo E2E로 확인한다.
- [ ] 지역·숫자·단위·시점이 F-002 결과와 일치한다.
- [ ] 앱 Callback은 제안 마감 내 한 번 처리하며 지연 응답을 발화하지 않는다.
- [ ] Gleo 응답과 앱 TTS가 중복되지 않는다.
