# F-008 스크랩과 변동 알림

## 목적

관심 있는 단지를 스크랩해 두고, 앱을 다시 열었을 때 그 단지 정보에 변동이 있으면 알려 준다.

## 사용자 가치

- 임장 중 눈여겨본 단지를 나중에 다시 확인한다.
- 스크랩한 단지의 새 거래 소식을 놓치지 않는다.

## 비즈니스 규칙

1. 스크랩은 홈, 상세, 주행 요약, 알림에서 할 수 있다.
2. 주행 중 스크랩은 한 번의 탭 또는 음성으로만 가능하며 허용 여부는 T-001 답변 후 확정한다.
3. 변동은 '새 실거래 등록', '가격 변화', '순위 변화'로 정의한다.
4. 앱 실행 시 스크랩 단지의 변동을 확인하고 홈에 변동 건수를 표시한다.
5. 확인한 변동은 '읽음'으로 표시해 다시 강조하지 않는다.
6. 스크랩 목록은 기기에 저장한다(제안값).

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | 스크랩 요청 | 단지 ID |
| 입력 | 최신 시세 | F-002 |
| 출력 | 스크랩 목록 | 단지, 스크랩 시각, 마지막 확인 값 |
| 출력 | 변동 목록 | 단지, 변동 종류, 이전 값, 현재 값 |

## 저장 데이터 설계

Room 테이블 `scraps`에 단지당 한 행을 저장한다(ADR-005). 서버로 보내지 않는다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `apartment_id` | 문자열, 기본 키 | 단지 ID. 데이터 출처(T-005)가 정해지면 단지 코드 |
| `name` | 문자열 | 단지명 |
| `neighborhood` | 문자열 | 동 이름 |
| `area_pyeong` | 정수 | 스크랩 당시 대표 거래 평형 |
| `scrapped_at` | 시각(epoch ms) | 스크랩한 시각. 목록 정렬 기준 |
| `baseline_price_manwon` | 정수 | 스크랩 당시 최근 실거래가(만원) |
| `baseline_deal_date` | 날짜(epoch day) | 스크랩 당시 최근 거래일 |
| `last_price_manwon` | 정수 | 마지막으로 확인한 최근 실거래가 |
| `last_deal_date` | 날짜 | 마지막으로 확인한 최근 거래일 |
| `last_checked_at` | 시각 | 마지막 변동 확인 시각 |
| `change_kind` | 문자열, 선택 | `NEW_DEAL`, `PRICE_UP`, `PRICE_DOWN`, `RANK_CHANGE` |
| `change_delta_manwon` | 정수, 선택 | 직전 확인 값 대비 가격 차이 |
| `change_detected_at` | 시각, 선택 | 변동을 발견한 시각 |
| `change_seen` | 불리언 | 사용자가 확인했는지(규칙 5) |
| `households` | 정수, 선택 | 세대수. v2(T-017)에서 추가. 마이 페이지 비교용 |
| `built_year` | 정수, 선택 | 준공연도. v2에서 추가 |

v1에서 v2로는 Room 자동 마이그레이션으로 두 열을 비워 둔 채 옮기고, 다음 변동 확인 때 단지 상세에서 채운다.

### 변동 판단

앱 실행 시(규칙 4) 스크랩마다 최신 실거래를 조회해 마지막 확인 값과 비교한다.

1. 최근 거래일이 더 늦으면 `NEW_DEAL`, 가격 차이를 `change_delta_manwon`에 기록
2. 거래일은 같고 가격만 다르면 `PRICE_UP` 또는 `PRICE_DOWN`
3. 같으면 변동 없음. 기존 변동 표시는 유지
4. 변동을 기록하면 마지막 확인 값을 최신 값으로 바꾸고 `change_seen`을 거짓으로 둔다.
5. 사용자가 상세 화면을 열면 `change_seen`을 참으로 바꾼다.

`RANK_CHANGE`는 순위 데이터(F-003) 연결 후 판단한다.

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 스크랩, 목록 확인, 변동 확인 |
| Drive | 스크랩만 가능(미확정), 목록 진입 불가 |
| 오프라인 | 목록 표시, 변동 확인은 연결 후 |
| API 미지원 | 해당 없음 |
| 백그라운드 | 변동 확인하지 않음(제안값) |

## 예외

- 스크랩 단지 데이터가 사라지면 '정보 없음'으로 표시하고 목록에서 지우지 않는다.

## 인수 조건

- [ ] 스크랩한 단지가 앱 재실행 후에도 유지된다.
- [ ] 새 실거래가 등록되면 다음 실행 시 변동으로 표시된다.
- [ ] 확인한 변동은 다시 강조되지 않는다.

## 관련 문서

## 미결 사항

- [ ] 변동 판단 주기와 비교 기준
- [ ] 스크랩 개수 상한
- [ ] 부부가 스크랩을 공유할지 여부
- [ ] 스크랩 단지의 조건별 만족도(0~5)와 조건 일치율 계산 방식(SCR-010)

## 관심 지역 브리핑과의 구분

스크랩의 대상은 단지 ID다. 법정동/역세권 저장은 [F-011](F-011-interest-area-booking.md), 해당 지역의 청약/뉴스/신규 공개 거래 요약은 [F-013](F-013-area-daily-briefing.md)에서 정의한다. 서로 다른 저장 키·읽음 체크포인트를 사용하고 기존 스크랩 변동을 지역 신규 공고로 바꾸지 않는다.
