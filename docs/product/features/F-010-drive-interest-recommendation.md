# F-010 주행 관심 매물 추천

## 목적

사용자가 온보딩에서 저장한 관심 조건과 기기에 저장한 선호 프로필에 따라 주행 중 차량 반경 10km에서 만난 아파트를 평가하고, 주행 종료 요약에 추천 후보 최대 3개를 제공한다. 기존 조건 일치 알림(F-005)은 유지하며 추천 노출과 알림 발송은 별도 정책으로 다룬다.

## 사용자 가치

- 주행을 마친 뒤 지나온 주변에서 취향에 맞는 단지를 세 곳까지 빠르게 확인한다.
- 조건에 잘 맞는 단지를 만났을 때 주행 중 허용된 간소 알림으로 놓치지 않는다.
- 스크랩과 실제 추천 상세 확인에 따라 추천 순서가 점차 개인화된다.

## 비즈니스 규칙

1. 입력은 저장된 `InterestCondition`, 위치가 확인된 주행 중 시장 후보, 주행 세션이다. 조건이 비어 있거나 건너뛴 경우 추천하지 않는다.
2. 추천 탐색 반경은 실제 차량 위치에서 10km로 한다. 임시 기준 위치, 위치 미지원, 유효하지 않은 위치로 생성한 결과는 주행 추천과 알림에 포함하지 않는다.
3. 각 위치/시장 갱신 때 후보를 세션 후보 집합에 합친다. 중복 단지는 안정 ID로 합치고 가장 가까운 거리와 최신으로 확인된 평가 정보를 보존한다. 앱 재시작 뒤에도 진행 중 세션의 후보가 유지되어야 한다.
4. 선택된 조건 항목별로 0~5 적합도 점수를 계산하고, 확인 가능한 선택 축의 평균을 종합 점수(0~100)로 사용한다. 정보가 없는 축은 평균에서 제외한다. 축별 가중치는 동일하다.
5. `main_reco_key`에는 해당 후보에서 가장 높은 축 점수의 코드(`PRICE`, `AREA`, `NEIGHBORHOOD`, `HOUSEHOLDS`, `NEWNESS`)를 저장한다. 동점 축은 이 순서로 결정한다. 화면 문구는 이 값을 후속 룰 기반 매핑에서 만든다.
6. 종합 점수 동점은 가까운 단지, 단지 ID 오름차순으로 정렬한다. 전체 후보를 점수 순으로 유지하고 요약 표시 계층은 상위 3개를 사용한다.
7. 거래가 기준은 현재 후보 대표값인 최근 1개월 최고 실거래가를 쓴다. 면적은 전용 면적 ㎡를 평으로 환산한 값이다.
8. 종료 요약에는 적합도 상위 3개만 카드로 표시한다. 실제 알림으로 노출된 추천은 추천 후보와 `passedInterests` 모두에 기록한다. `관심 매물 모아보기`에는 전체 추천 후보와 추천 후보에 없는 지나친 관심 매물을 중복 없이 표시한다.
9. 추천 상위 3개 중 실제 차량 2km 이내로 접근한 단지는 기존 F-005/F-006 알림 배너에 표시한다. 알림 동의, 스크랩 제외, 단지별 24시간 억제, 위치 갱신당 최대 1건을 적용한다. 노출된 알림 단지는 알림 시점의 가장 가까운 거리와 함께 세션의 지나친 관심 매물 기록에 영속화한다. 점수 재정렬만으로 반복 알림하지 않는다.
10. 주행 중 기능은 주행 제한 상태에서 기존 간소 알림 경로만 사용한다. 상세 탐색/UI 진입은 포함하지 않는다. 화면/TTS 허용 조건은 T-001 및 F-006 미결을 따른다.
11. 후보와 점수는 기기 내 주행 세션에 저장하고 원좌표·이동 경로는 저장하지 않는다.
12. 데이터 수집은 위치/지역 변경 이벤트와 기존 시장 갱신에 결합하며 별도 고빈도 폴링을 추가하지 않는다.
13. 추천 입력은 명시적 관심 조건과 현재 활성 스크랩의 가격·면적·동네·세대수·연식 속성을 사용한다. 추천 상세를 연 단지는 SCR-008/SCR-011의 추천 카드에서 연 경우만 약한 긍정 신호로 로컬 집계한다.
14. 신호가 적을 때는 기존 명시 조건 점수가 중심이고, 유효한 선호 예시가 늘면 행동 프로필 비중을 점진적으로 올린다. 명시 조건 점수는 항상 유지한다.
15. 추천에 노출되었으나 사용자가 열지 않은 것은 부정 반응으로 기록하지 않는다. 상세 열기 수는 단지별 최대 10회로 제한한다. 활성 스크랩은 별도 선호 예시로 반영하고 스크랩 해제 후에는 해당 활성 스크랩 신호를 제거한다.
16. 프로필과 상세 열기 집계는 기기에만 저장한다. 서버로 전송하지 않고, 좌표·주행 세션 ID·원시 탭 시각은 반응 데이터에 저장하지 않는다. 설정의 데이터 삭제는 이 집계도 지운다.

현재 후보 원천은 최근 1개월 내 실거래가 있는 단지다. 차량 반경 10km 경계 상자와 교차하는 시군구들의 거래를 가져와 실제 좌표 거리로 거른다. 새 주소 지오코딩은 시장 갱신당 최대 18개이며 확인된 좌표만 후보에 들어간다. 따라서 좌표 확인 전인 단지, 거래가 없는 단지, 호가 매물은 후보에 없고 모든 10km 거래 단지를 한 번에 전수 확인한다고 보장하지 않는다.

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | 관심 조건 | F-004의 기기 저장 조건 |
| 입력 | 주변 아파트 후보 | F-002 시장 데이터, 실제 위치로 검증된 거리, 거래/단지 속성 |
| 입력 | 세션 식별자 | F-009 주행 세션 |
| 입력 | 선호 프로필 | 활성 스크랩 속성 및 추천 카드에서 상세를 연 단지의 제한된 집계 |
| 출력 | 추천 후보 | 단지 ID, 표시 정보, 적합도, `main_reco_key`, 거리, 순위 |
| 출력 | 추천 알림 후보 | 한 위치 갱신에서 최대 한 단지 |
| 저장 | 세션 후보 집합 | Room 세션 종속 기록, 최근 10개 요약과 함께 정리 |
| 저장 | 추천 반응 | 상세 열기 단지별 최신 추천 속성, 제한된 횟수. 기기 내 보관 |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 추천 계산·알림 없음. 종료된 요약의 추천을 조회한다. |
| Drive | 유효한 차량 위치와 시장 결과 갱신 시 로컬 선호 프로필로 후보를 누적·재평가한다. 사용자 상호작용은 기록하지 않는다. |
| 오프라인 | 세션 안에서 이미 유효하게 관측·저장된 후보만 유지하고 신규 후보 없음 |
| API 미지원 | 위치 또는 시장 자료를 확인할 수 없으면 신규 추천·알림 없음 |
| 백그라운드 | 기존 주행 기록 생명주기 안에서 후보 계산만 한다. 별도 서비스 정책은 추가하지 않는다. 알림은 F-006 허용 범위 적용 |

## 예외

- 조건 없음, 유효 위치 없음, 후보 없음이면 추천 목록은 비어 있다.
- 단지 ID가 안정적으로 정해지지 않거나 필수 자료가 부족하면 후보를 중복 집계하지 않도록 제외하거나 점수 계산에서 제외한다.
- API 오류가 나도 이미 저장한 세션 후보와 기존 요약은 보존한다.
- 스크랩/상세 반응 데이터가 없거나 속성 축을 알 수 없으면 해당 암묵 축을 제외하고 명시 조건 점수로 추천한다.
- 기어 P로 세션이 끝나면 저장된 후보로 최종 상위 3개를 만든다. 이미 생성된 세션 후보가 없으면 빈 목록이다.

## 인수 조건

- [ ] 거리 10km 경계 안 후보만 평가하고 10km 밖 후보와 임시 기준 위치 후보는 주행 후보에서 제외한다.
- [ ] 동일 단지의 반복 관측은 한 추천 후보로 합쳐지고 가장 가까운 거리로 갱신된다.
- [ ] 조건이 비었거나 건너뛰어진 경우 추천·추천 알림이 생성되지 않는다.
- [ ] 후보 점수와 동점 정렬은 같은 입력에서 결정적으로 재현된다.
- [x] 스크랩 속성 또는 추천 카드 상세 열기 반응이 추가되면 같은 후보의 개인화 점수가 달라질 수 있고, 입력이 같으면 재현 가능하다(T-047).
- [x] 추천 카드 노출만으로 피드백을 저장하지 않으며 상세 열기 집계는 단지별 최대 10회다(T-047).
- [x] 일반 상세 진입은 추천 반응으로 기록되지 않고, 추천 카드에서 상세 진입했을 때만 기록된다(T-047).
- [x] 사용자 데이터 전체 삭제 후 추천 반응 집계도 0건이다(T-047).
- [ ] 주행 중 관측한 후보가 앱 프로세스 재시작 후에도 같은 세션 요약에 반영된다.
- [ ] 종료 요약은 추천을 0~3개 표시 데이터로 제공하며 기존 지나친 관심 매물 기록을 보존한다.
- [ ] 신규 위치 관측이 없거나 오프라인이면 기존 후보를 삭제하지 않는다.
- [ ] 알림은 동일 단지 억제 정책과 위치 갱신당 최대 1건 제한을 지킨다.
- [ ] 10km 전 후보 수집과 점수 계산이 측정되어 PF-002/004 기준을 확인한다.
