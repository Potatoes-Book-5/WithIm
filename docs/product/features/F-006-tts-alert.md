# F-006 알림과 TTS 안내

## 목적

관심 매물 발견(F-005)과 대장 교체(F-003)를 짧은 화면 알림과 TTS로 전달한다.

## 사용자 가치

- 운전 중 화면을 보지 않고도 소식을 듣는다.
- 동승한 배우자도 함께 듣고 이야기할 수 있다.

## 비즈니스 규칙

1. 알림 종류는 '관심 매물 발견'과 '대장 교체' 두 가지이다.
2. TTS 문구는 한 문장으로, 재생 시간은 제안값 5초 이내로 한다.
3. 화면 알림은 자동으로 사라지며 표시 시간은 제안값 8초이다.
4. 내비게이션 안내 중에는 끼어들지 않고 오디오 포커스 정책을 따른다.
5. 알림이 여러 개 쌓이면 최신 1건만 읽고 나머지는 주행 요약에 남긴다.
6. 광고로 보이는 표현을 쓰지 않는다(DG-010).
7. 사용자는 알림 종류별로 켜고 끌 수 있다(F-007).

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | 알림 이벤트 | F-003, F-005 |
| 출력 | TTS 재생 | TextToSpeech SDK |
| 출력 | 화면 알림 | SCR-005 |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 화면 알림만 표시, TTS 선택 |
| Drive | TTS와 간소 알림, 주행 중 허용 범위는 T-001 답변 후 확정 |
| 오프라인 | 캐시 기반 이벤트만 알림 |
| API 미지원 | TTS는 전체 호환(CP-003) |
| 백그라운드 | 허용 여부 미확정(T-001) |

## 예외

- 오디오 포커스를 얻지 못하면 TTS를 건너뛰고 화면 알림만 표시한다.
- 재생 중 포커스를 잃으면 즉시 중단하고 다시 읽지 않는다(제안값).

## 인수 조건

- [ ] 두 알림 종류의 문구가 정해진 길이를 넘지 않는다.
- [ ] 내비 안내 재생 중에는 TTS가 끼어들지 않는다.
- [ ] 꺼 둔 알림 종류는 재생되지 않는다.

## R-AUDIO — Gleo 요청과 추가 알림

모든 앱 음성은 포커스 획득 후 재생한다. 제품의 부동산 알림은 내비 안내/통화/긴급 안내를 방해하지 않게 설계하고 플랫폼 상호작용 정책을 따른다. Gleo 시작으로 포커스를 잃으면 앱 음성을 중단한다. 포커스 거부 시 강제 재생하지 않는다. 자동 진입 알림이 지연된 동안 지역을 벗어나면 폐기하고 기록만 남긴다.

이 문서의 한 문장/5초 제안은 기존 관심 매물·대장 교체 등 짧은 앱 알림에 적용한다. F-010의 사용자 질의응답과 F-013의 요청형 브리핑을 5초 음성으로 강제하지 않는다. 앱 Callback 기한과 음성 재생 길이는 다른 지표다.

지역 진입(F-011)·자동 브리핑(F-013)의 자동 출력은 별도 지원·허용 검증 전 비활성이다. 앱 자체 TTS 대안도 자동 승인된 것으로 간주하지 않는다. 검증: [S-011 테스트](../../testing/gleo-tour/README.md).
