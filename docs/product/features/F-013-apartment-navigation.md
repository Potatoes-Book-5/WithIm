# F-013 단지 방문 내비게이션

## 목적

주차 중 선택한 단지의 방문 가능한 출입구로 Pleos Navigation 경로 안내를 요청한다.

## 사용자 가치

- 추천 단지를 다시 검색하지 않고 현장 방문으로 연결한다.

## 비즈니스 규칙

- 주차 중 선택한 단지의 방문 가능한 차량 출입구 좌표와 주소를 표시하고 ‘경로 안내’로 요청한다. MVP에서는 추가 Gleo 함수를 사용하지 않는다.
- 기존 경로가 있으면 교체 여부를 확인한다. 거부/취소하면 기존 경로를 유지한다.
- 단지 중심점이 도로 밖이거나 출입구가 불명확하면 경로를 임의로 시작하지 않고 출입구를 선택하게 한다.
- NaviHelper의 실제 성공/안내 상태 이벤트 확인 전에는 ‘안내 시작 완료’로 표시하지 않는다. 미지원/권한 없음/연결 실패 시 주소를 제공하고 성공을 가장하지 않는다.
- 오프라인 경로 가능 여부는 내비 서비스의 결과를 따른다. 앱이 보장하지 않는다. 중복 탭은 한 요청으로 합친다.

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | 단지 ID·출입구 좌표/주소·현재 경로 | 단지 중심점과 출입구 구분 |
| 출력 | 요청/안내 상태 | 요청 중, 확인 필요, 안내 시작, 실패 |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 출입구 확인과 경로 요청 |
| Drive / 신호 대기 | 신규 경로 선택 UI 차단. 이미 시작된 내비는 시스템이 담당 |
| 오프라인 | 내비 서비스 결과를 따르며 주소는 표시 |
| API 미지원 | 주소 제공, 성공 표시 금지 |
| 백그라운드 | 이미 제출한 요청 결과만 상태/프로필 검증 후 반영 |

## 예외

- 기존 경로 교체를 취소하면 유지한다.
- 출입구가 불명확하면 임의 중심점으로 경로를 시작하지 않는다.
- 늦은 콜백과 중복 탭이 중복 요청을 만들지 않게 한다.

## 인수 조건

- [ ] 선택 출입구 좌표가 SDK 요청과 일치한다.
- [ ] 접수만으로 안내 시작 완료로 표시하지 않는다.
- [ ] 미지원·권한·내비 실패를 구분한다.
