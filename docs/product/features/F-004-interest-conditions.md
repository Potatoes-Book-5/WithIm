# F-004 관심 조건 설정

## 목적

앱 첫 실행 시 관심 있는 부동산 조건(동네, 가격대, 평수)을 설정하고 이후 수정할 수 있게 한다.

## 사용자 가치

- 부부가 함께 원하는 조건을 한 번 정해 두면 이동 중 알아서 알려 준다.

## 비즈니스 규칙

1. 첫 실행 시 동의(F-007) 다음에 조건 설정 화면을 보여 준다. 건너뛸 수 있다.
2. 조건 항목은 동네, 가격대, 평수이며 최소 1개 이상 선택해야 저장된다.
3. 동네는 현재 위치 주변 추천, 최근 지나간 동네, 음성 검색으로 고른다. 키보드 입력은 보조 수단이다.
4. 가격대와 평수는 미리 정한 구간 칩으로 고른다.
5. 조건 수정은 주차 중에만 가능하다.
6. 조건은 기기에 저장하고 서버로 보내지 않는다(제안값).

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | 동네 | 행정동 또는 법정동, 여러 개 |
| 입력 | 가격대 | 구간 선택, 여러 개 |
| 입력 | 평수 | 구간 선택, 여러 개 |
| 출력 | 관심 조건 | domain `InterestCondition` |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 설정과 수정 가능 |
| Drive | 수정 불가, 저장된 조건만 사용 |
| 오프라인 | 동네 추천은 캐시 기반, 저장 가능 |
| API 미지원 | 위치 미지원 시 주변 추천 대신 음성 검색 안내 |
| 백그라운드 | 해당 없음 |

## 예외

- 조건 없이 건너뛰면 관심 매물 알림(F-005)은 꺼진 상태로 시작한다.

## 인수 조건

- [ ] 첫 실행 흐름에서 조건 화면이 표시되고 건너뛸 수 있다.
- [ ] 주행 중에는 조건 수정 진입이 막힌다.
- [ ] 앱을 다시 실행해도 저장한 조건이 유지된다.

## S-011 임장 추천 제안

예산과 면적은 필수 필터다. 선호 점수는 선택한 선호 항목의 정규화 값에 가중치를 적용한다. 초기 제안은 대중교통 접근성 60%, 공원 접근성 40%이며 둘 다 데이터가 있는 후보에만 계산한다. 정규화는 0~2km 구간에서 거리 증가에 따라 100→0으로 선형 감소하고 범위를 벗어나면 끝값으로 제한한다. 데이터가 부족한 후보는 추천 점수를 만들어내지 않고 ‘입지 정보 부족’으로 별도 표시한다. 동률은 가격이 낮은 후보, 단지 ID 순으로 정렬한다. 개인화 점수는 자산 가치·수익률 평가가 아니다.

- F-004의 최초 조건 설정은 일부 조건만으로 저장할 수 있는 기존 흐름을 유지한다. 다만 가격/면적을 전제하는 임장 맞춤 추천은 해당 조건이 없으면 설정 필요로 표시하고 개인화했다고 말하지 않는다.
- 조건을 만족하는 후보가 1~2개면 해당 수만 제공하며 가짜 3위를 만들지 않는다.
- 이 점수는 [SCR-010](../../design/screens/SCR-010-my-page.md)의 채택된 5축 스크랩 비교 시안과 별개다. 오각형·기존 팀 결정·그 계산식을 대체하지 않는다.
- 가중치/필수 조건의 채택은 미결이다. 검증은 [S-011 테스트](../../testing/gleo-tour/README.md), 합성 기대값은 fixtures.json을 따른다.
