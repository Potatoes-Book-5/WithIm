# F-013 관심 지역 데일리 브리핑

## 목적

저장한 지역의 새 실거래·청약·뉴스를 요청형으로 전달한다. 시동 자동형은 지원 검증 전 비활성이다. F-008의 단지별 변동과 별도 범위다.

## 사용자 가치

- 다음 탑승에서도 이전 임장 관심 지역의 새 정보를 이어서 확인한다.

## 비즈니스 규칙

### R-06 — 브리핑

- MVP 트리거: 앱 실행 후 브리핑 선택 또는 ‘관심 지역 새 소식 알려줘’라는 Gleo 요청.
- 자동형 트리거: 검증된 탑승/시동 또는 resume 이벤트, 활성 프로필 확정, 자동 안내 opt-in, 실행 허용, 오디오 포커스 조건을 모두 만족할 때. API 검증 전 비활성이다.
- 관심 지역의 새 실거래, 새 청약 공고, 사용자가 선택한 뉴스 주제를 최대 3개 카드로 요약한다. 출처·게시/거래일·수집일을 구분한다.
- ‘새로운 소식’은 원천 안정적 ID/버전과 프로필별 마지막 열람 체크포인트로 판단한다. 늦게 공개된 과거 거래는 ‘새로 공개된 거래’라고 표현하며 ‘오늘 거래’로 바꾸지 않는다.
- 모든 공급자의 결과를 성공으로 간주하지 않는다. 청약 조회 실패면 해당 유형 실패를 표시하고 체크포인트를 갱신하지 않는다.
- 읽음 체크포인트는 실제 카드 열람 또는 음성 완료 후 해당 항목 단위로 갱신한다. 네트워크 fetch나 Gleo Callback 전송만으로 읽음 처리하지 않는다. Gleo 음성 완료 이벤트가 확인되지 않으면 카드 열람/사용자 확인으로만 갱신한다.
- 요청형은 같은 날 재열람 가능하다. 자동형은 프로필별 로컬 날짜당 최대 1회 완료, 중단/실패는 완료로 간주하지 않는다. 당일 자동 재시도는 하지 않고 요청형으로 전환한다.
- 통화·긴급 안내 등으로 출력이 거부되면 끼어들지 않는다. 뉴스 플래시는 자동 스크롤/점멸이 아닌 정적 카드로 제공하며 주행 화면 허용을 따른다.
- 오프라인은 기존 브리핑에 과거 기준일을 붙여 열람할 수 있다. 새 소식 유무를 단정하지 않는다. 프로필이 확정되지 않으면 개인 정보를 읽지 않는다.
- 인수 조건: 어제 저장한 관심 지역이 다음 세션에도 연결되고 중복 공고는 한 건이며, 데이터 없음과 조회 실패가 구분된다.

## 입출력 데이터

| 구분 | 항목 | 설명 |
|---|---|---|
| 입력 | 활성 프로필의 InterestArea, 원천별 체크포인트 | F-011, F-007 |
| 저장 | BriefingItem | 원천 ID/버전, 지역, 유형, 게시/거래일, 수집 시각, 읽음 상태 |
| 출력 | 최대 3개 요약 카드와 요청형 음성 | 출처/기준일/부분 실패 표시 |

## 상태별 동작

| 상태 | 동작 |
|---|---|
| Parking | 요청형 열람·상세 이동 |
| Drive / 신호 대기 | 허용된 음성/간소 정적 카드만; 미확인 시 비활성 |
| 오프라인 | 과거 캐시 표시, 신규 여부 단정 금지 |
| API 미지원 | Gleo 또는 자동형을 가장하지 않고 주차 후 앱 열람 |
| 백그라운드 | 시동/resume/자동 발화 지원·승인 전 비활성 |

## 예외

- 유형별 API 실패 시 해당 유형 체크포인트 유지.
- 프로필 불명/전환 중에는 개인 지역 발화 금지.
- Callback 전송만으로 실제 음성 청취 완료를 추정하지 않는다.

## 인수 조건

- [ ] 저장 지역이 다음 세션 브리핑에 연결된다.
- [ ] 지연 공개를 오늘의 신규 계약으로 읽지 않는다.
- [ ] 실제 열람/검증된 음성 완료 또는 확인 이후 항목 단위로 읽음 갱신한다.
- [ ] 자동형 미지원이면 요청형으로만 실행한다.
