## R-MODE — Gleo 임장 상세 진입 정책

아래는 본 제품의 보수적인 제안 정책이며 모든 지역의 법규를 요약한 표가 아니다. 플랫폼 제한이 더 엄격하면 플랫폼이 우선한다. 앱 카테고리와 DO 선언의 적합성을 확인하기 전까지 주행 기능은 출시 비활성이다.

| 상태 | 판정 | 음성 조회/저장 | 간소 순위/카드 | 상세 그래프/설정 | 카메라 영상 |
|---|---|---|---|---|---|
| 주행 | 플랫폼 제한 적용 또는 이동 중 | 허용 확인 시만 | 허용 확인 시만, 정적 Top 3 | 차단 | MVP 없음 |
| 신호 대기 | 속도 0이나 주차 확정 아님 | 주행과 동일 | 주행과 동일 | 차단 | MVP 없음 |
| 주차 준비 완료 | 속도 0 + P단/플랫폼 주차 상태 확인 + UX 제한 해제 | 사용 | 사용 | 사용 | 확장 승인 시 별도 조건 |
| 상태 불명/신호 만료 | 제한/차량 상태를 신뢰할 수 없음 | 승인된 백그라운드 경로만; 미확인 시 안내 후 실패 | 제한 안내 | 차단 | 차단 |

- P단이어도 CarUxRestrictions가 활성인 동안 상세 화면은 열리지 않는다.
- 속도·기어를 읽을 수 없다면 임의의 값으로 주차 상태를 추정하지 않는다. 플랫폼 주차 판정의 대체 경로를 검증하기 전까지 상세 화면을 잠근다.
- 상세 화면에서 제한 이벤트를 받으면 다음 렌더부터 상세·입력을 제거한다. 제안 QA 상한은 이벤트 수신 후 250ms이다. 물리적 차량 상태 감지 지연과 구분하여 측정한다.
- 진행 중 요청도 완료 시점에 권한·프로필·UX 상태를 다시 검사한다. 주행으로 바뀐 뒤 도착한 상세 응답으로 화면 잠금을 해제하지 않는다.
- 동승자의 존재나 발화만으로 운전자용 공용 화면의 제한을 해제하지 않는다. 별도 동승자 디스플레이 지원은 이번 범위 밖이다.

차량 상태 freshness와 이벤트 처리 목표는 [제안 기본값](gleo-tour-defaults.md)을 따른다. 검증: [S-011 테스트](../testing/gleo-tour/README.md).
