# Gleo 임장 제안 기본값

이 문서는 [S-011](scenarios/S-011-conversational-property-tour.md)의 수치 제안 원본이다. 확정된 플랫폼 수치나 구현 완료 기준이 아니다. 기능 문서와 테스트의 수치는 이 표에 대한 인수 조건이며 변경 시 함께 검토한다. 기존 F-005의 단지 근접 알림 거리·F-003의 대장 교체 간격은 각각의 기능 문서에 유지한다.

| 설정 | 제안값 | 경계 의미 |
|---|---|---|
| 지역 조회 문맥 TTL | 60초 | 경과 <= 60초 유효 |
| 현재 위치 최대 경과 | 10초 | 경과 <= 10초 유효 |
| 위치 오차 반경 | 50m | <= 50m 및 지역 경계 비중첩 |
| 차량 상태 최대 경과 | 2초 | > 2초이면 상세 잠금 |
| 실거래 기간 | 90일 | 조회 로컬 날짜 포함 최근 90일, 시작 포함/다음날 00:00 제외 |
| 기본 전용면적 | [80, 90)㎡ | 하한 포함, 상한 제외 |
| 평균 최소 표본 | 3건 | 2건 이하는 표본 부족 |
| 가격 순위 반경 | 10km | 직선거리 <= 10,000m 포함 |
| 역세권 진입/재무장 | 500m / 600m | <=500 진입, >=600 이탈 확정 |
| 지역 알림 최소 간격 | 10분 | 경과 >=10분 및 신규 진입 시 가능 |
| 오프라인 요약 캐시 | 24시간 | 수집 후 <=24시간 사용, 기준시각 안내 |
| 앱 Gleo 처리 기한 | 5초 | 마감 시 fail 처리, 늦은 성공 응답 폐기 |
| 자동 브리핑 완료 상한 | 로컬 날짜당 1회 | 중단은 완료 아님; 당일 자동 재시도 없음 |

이는 검증 가능한 초기 기준을 만들기 위한 제안이다. 공식 문서의 숫자는 Gleo 7초 timeout 등 출처를 명시한 항목뿐이며, 제품 제안값은 승인 전 변경할 수 있다.

## 적용 범위와 검토

- 위치 10초/오차 50m는 현재 법정동을 해석하는 Gleo 요청과 관심 지역 진입 판정의 제품 조건이다. F-001의 일반 순위 갱신 조건과 구분한다.
- 법정동은 공간 경계, 역세권은 중심+반경이다. 근접 API에 동 경계를 원형으로 가장해 전달하지 않는다.
- 실거래 계산 규칙은 [F-002](features/F-002-nearby-price-lookup.md), 추천 산식은 [F-004](features/F-004-interest-conditions.md), 가격 순위는 [F-003](features/F-003-apartment-ranking.md)이 소유한다.
- 카테고리·DO·개인정보 처리 방식과 보관기간은 승인하지 않았다. [시나리오의 미결 사항](scenarios/S-011-conversational-property-tour.md)을 검토한 뒤 확정한다.

## T-043 현재 가격 실행 경로

위 S-011 초기 제안 표와 현재 실행 정책을 혼동하지 않는다. 실제 가격 API는 F-002/T-038의 달력 3개월(`today.minusMonths(3)`~당일 포함), T-041의 5분 prepared cache를 사용한다. 90일·24시간 캐시를 제공한다고 응답하지 않는다. 공개 debug 요청은 명시한 준비된 시군구만 허용하며 위치/직전 지역은 인증 확인 전 비활성이다.
